# KITEZH

Внутренняя информационная система КРНО для ведения обращений, координации задач,
подготовки документов и анализа карточек инвестиционных площадок Нижегородской области.

> Система разворачивается локально. Рабочая SQLite-база, загруженные документы,
> отчёты, настройки окружения и иные пользовательские данные не хранятся в Git.

## Основные возможности

### Обращения и работа с инвесторами
- Регистрация, просмотр, редактирование и поиск обращений
- Назначение ответственных и соисполнителей
- История изменений, уведомления и разграничение прав
- Карточка инвестора и связь с контактами по ИНН
- Прикрепление файлов и OCR-извлечение данных из анкет

### Задачи и документы
- Постановка и контроль задач, статусы, комментарии и история выполнения
- Журнал исходящих и входящих писем
- Шаблоны документов и работа с контрагентами
- Экспорт рабочих выборок и отчётов

### Инвестиционные площадки
- Ведение и проверка сведений по карточкам площадок
- Модуль анализа заполненности карточек
- Расчёт V1 и V2 с учётом зависимых полей и условных исключений
- Перечень незаполненных полей с подсказками для корректировки карточки
- Правила проверки и логика расчёта: [portal_analysis/PORTAL_LOGIC.md](portal_analysis/PORTAL_LOGIC.md)

### Администрирование
- Управление пользователями, ролями и правами
- Настройка справочников и классификаторов
- Миграции структуры базы данных
- Журнал действий и служебные инструменты

## Технологии

- Python и Flask
- SQLite
- Jinja2, Bootstrap и Tabulator
- openpyxl для экспорта Excel
- python-docx для DOCX
- pytesseract и Pillow для OCR
- dotenv для конфигурации окружения

Полный список Python-зависимостей приведён в [requirements.txt](requirements.txt).
Отдельные OCR-зависимости — в [requirements-ocr.txt](requirements-ocr.txt).

## Быстрый запуск

### Windows: штатная установка

1. Клонируйте или скачайте репозиторий.
2. Запустите `install.bat`.
3. При необходимости OCR запустите `install_ocr.bat`.
4. Запустите `start KITEZH.bat`.
5. Откройте адрес, который выведет приложение.

### Запуск из исходников

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Для OCR дополнительно установите Tesseract OCR и зависимости из
`requirements-ocr.txt`, затем проверьте параметры в конфигурации приложения.

## Данные и безопасность

- Не добавляйте в Git SQLite-базы, файлы обращений, выгрузки, резервные копии и `.env`.
- Не размещайте в исходном коде пароли, токены, адреса рабочих сервисов и персональные данные.
- Перед обновлением рабочей версии создавайте резервную копию БД и пользовательских файлов.
- При изменении схемы данных добавляйте безопасную миграцию и проверяйте её на копии рабочей БД.

## Порядок разработки

1. Создайте тематическую ветку от актуального `main`.
2. Внесите изолированное изменение и проверьте его локально.
3. Обновите документацию, если поменялись интерфейс, логика, структура данных или запуск.
4. Зафиксируйте изменение понятным коммитом.
5. Создайте Pull Request или согласуйте слияние в `main`.

Для изменений, затрагивающих расчёт оценки площадок, необходимо отдельно проверять
контрольные карточки и случаи условного исключения зависимых полей.
